# 技术架构设计：AI 拟人写作平台

> 版本 V1.0 ｜ 2026-10-11 ｜ 目标：小团队（4~5 人）可落地的成熟技术栈，支撑 iOS App + Web 工作台

**关键架构决策（ADR）**

| 决策 | 选择 | 理由 |
|---|---|---|
| 单体 vs 微服务 | **模块化单体**（NestJS 模块边界清晰） | 4~5 人团队微服务是自杀；按域拆模块，未来可拆 |
| 同步生成 vs 异步 | **SSE 实时流 + 异步任务双轨** | 单篇实时 SSE 体验；批量生成走任务队列 |
| LLM 编排 | **自研薄网关（OpenAI 兼容协议）**，不用 LangChain/Dify | 主流国产模型都有 OpenAI 兼容接口，编排逻辑（模板→提示词→模型路由）是自己业务核心，框架反而碍事 |
| AI 率检测 | **自建三层：启发式特征 + 轻量分类器 + 第三方 API 兜底** | 朱雀无公开 API；完全依赖第三方有中断风险 |
| 计费一致性 | **冻结→扣减/解冻**（两阶段） + 流水表 | 生成失败必须退款，防止焦耳纠纷 |

## 3. 核心模块设计

### 3.1 生成流水线（最核心的时序）

```
POST /api/v1/works/generate
  1. 鉴权 → 2. 内容安全预检(输入主题) → 3. 焦耳冻结(jouel_freezes)
  4. 创建 work(status=generating) + generation_task 入队
  5. Worker: 装配提示词(prompt_version + 用户输入 + 模板参数)
  6. [enable_web_search] 调博查: 主题→3子查询→references(入库)
  7. [enable_think] 选 R1 类推理模型; 否则 chat 模型, temperature 按模板
  8. 流式产出: SSE 逐 event 推给客户端(经 Redis Pub/Sub 中转, 支持断线续传)
  9. 完成: 内容机审 → AI率检测 → 落库 → 焦耳实扣 → 生成检测报告
  10. 失败任意步: 焦耳解冻 + SSE error 事件
```

### 3.2 SSE 协议设计（对齐焦圈儿实测协议，可直接复用）

```
event: stage        data: {"stage":"searching","text":"正在联网检索资料..."}
event: search_end   data: {"references":[{title,url,site_name,summary}...]}
event: stage        data: {"stage":"outlining","text":"正在构思大纲..."}
event: delta        data: {"text":"正文增量..."}          # 逐段推送
event: stage        data: {"stage":"detecting","text":"AI率检测中..."}
event: report       data: {"ai_rate":18,"level":"human","rewrite_free":true}
event: done         data: {"work_id":"w_xxx","joule_cost":1000}
event: error        data: {"code":"MODEL_TIMEOUT","message":"...","refunded":true}
```
- 断线续传：`GET /api/v1/works/{id}/stream?seq=N`（事件带递增 seq，存 Redis 保留 10 分钟）。

### 3.3 LLM 网关（模型路由表驱动）

```jsonc
// config: model_routes
{ "default_chat":   { "provider":"deepseek", "model":"deepseek-chat", "fallback":["kimi","qwen-max"] },
  "think":          { "provider":"deepseek", "model":"deepseek-reasoner" },
  "title_gen":      { "provider":"doubao",   "model":"doubao-pro-32k", "temperature":1.0 },
  "ai_rate_rewrite":{ "provider":"deepseek", "model":"deepseek-chat", "temperature":1.1 } }
```
- 职责：统一 OpenAI 协议、多 key 轮换与限流、失败降级链、token 计量（成本核算到模板）。

### 3.4 AI 率检测（三层）

1. **启发式层**（实时，0 成本）：连接词密度、句长方差、段落长度分布、AI 高频词命中率 → 0~100 分；
2. **模型层**：微调小型分类器（如 bert-base-chinese，正样本=各模型裸输出、负样本=公众号历史爆款文章），自部署 GPU 推理或 CPU 量化；
3. **第三方层**（用户主动"深度检测"时调用）：Originality.ai / Copyleaks 等按次付费。
> 对外展示口径对齐朱雀分段：<50% 人工特征、50~99% 疑似、99~100% 明确 AI。

### 3.5 计费与 IAP

- **焦耳账本**：单用户单账户，余额 = 冻结 + 可用；所有变动写 `joule_transactions`（幂等键防重复）；
- **IAP 流程**：客户端购买 → receipt 发服务端 → App Store Server API v2 验签 → 幂等入账；订阅状态靠 App Store Server Notifications V2 webhook 同步（续费/退款/降级）；
- **Web 支付**（二期）：微信 Native/JSAPI + 支付宝，统一走 `orders` 状态机。

## 7. 部署与容量

**MVP 起步配置**（月成本估算 ≈ ¥3,000~5,000 + 模型/搜索按量）：
- 2×2C8G 云主机（Docker Compose：NestJS×2 + PostgreSQL + Redis + Nginx）
- OSS+CDN 按量；博查搜索 ~¥0.03/次；DeepSeek ~¥1~4/百万 token（千字成本约 ¥0.01~0.03，毛利率极高）
- 上量后：PG 读写分离 → 任务 Worker 独立扩容 → K8s

**黄金指标告警**：生成成功率<95%、SSE 断流率>5%、P95 生成时延>180s、模型渠道错误率>5%。

## 8. 安全清单

- JWT RS256（私钥仅签发服务持有）+ refresh token 轮换；
- 全接口限流（IP+用户双维度，Redis 令牌桶）；生成接口人机校验防刷焦耳；
- 提示词不落客户端（模板详情接口只回 usage_example，不回 system_prompt——焦圈儿正是这么做的）；
- 越权防护：work 属主校验；管理后台独立域名+IP 白名单；
- 数据合规：手机号加密存储、注销即删（Apple 要求）、日志脱敏。
