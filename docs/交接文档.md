## 1. 项目是什么（一段话）

**MyJQR 是一个对标「焦圈儿」的 AI 写作平台（Web 版）**：用户选一个"写作滤镜"（模板），输入一句话，系统联网搜索 → 调大模型流式生成 → AI 率检测 → 输出成文，按模板扣"焦耳"积分计费。本仓库包含**全部产品文档 + 可运行的前后端代码 + 模板提示词资产**。

**来龙去脉**（详见 docs/产品方案/）：逆向调研了焦圈儿的官网/App/接口（模板分类、cursor 分页、博查搜索、SSE 协议、计费体系全部摸清）→ 产出 6 份产品文档（调研/PRD/架构×2/计划/核心链路）→ 按"Python + Vue + MySQL + Redis + ARQ"栈实现了可跑的 MVP 骨架。

## 4. 跑起来（浓缩 5 步，详版见 docs/本地运行手册.md）

```bash
# ① 数据库（Docker Desktop 已装好）
cd MyJQR && docker compose up -d mysql redis

# ② .env：从 .env.example 复制，填 DEEPSEEK_API_KEY
#    （主机名已默认 localhost；本机 3306 被原生 MySQL80 占用 → MySQL 走 13306，见 .env 注释）

# ③ 后端初始化（用仓库根 .venv）
cd backend && pip install -r requirements.txt
python -X utf8 -m app.seeds                 # 建表+15分类+10内置模板+admin账号
python -X utf8 -m scripts.import_prompts    # 导入 xlsx 里的 54 个提示词模板
                                             #（先 --dry 可预览；可重复执行，幂等）

# ④ 起两个后端进程（各开一个终端，或用 PyCharm 运行配置——手册第七章）
uvicorn app.main:app --reload --port 9000    # API
arq app.tasks.worker.WorkerSettings          # ARQ worker（真正调模型的）

# ⑤ 前端两个终端
cd apps/web   && npm i && npm run dev        # 用户端 http://localhost:8080
cd apps/admin && npm i && npm run dev        # 后台 http://localhost:8081/admin/
```

## 5. 核心原理速览（5 分钟懂）

**生成一条文章的链路**（`POST /api/v1/works/generate` 触发）：
```
鉴权限流 → 输入敏感词预检 → 冻结焦耳(两阶段第1段) → 建 work + 投递 ARQ
→ worker: 装配提示词(prompt_versions 表) → 博查搜索(可选,拆3子查询)
→ LLM 流式(DeepSeek主/GLM备, reasoner=深度思考) → SSE 逐字推送
→ 阿里云机审(先审后显) → 启发式 AI 率检测 → 落库+结算焦耳(失败自动退款)
```

**三个关键设计**：
1. **模板=配置包**：system_prompt + user_prompt_template + 模型路由 + 参数 + 定价，存库且**版本化**（改提示词=新增版本，历史保留）；提示词**永不下发客户端**；
2. **焦耳两阶段扣费**：冻结→结算/解冻，所有变动写流水表，`idempotency_key` 唯一约束保证幂等（失败必退款、重复请求不重复扣）；
3. **SSE 事件流**：stage/search_end/delta/report/done/error 六种事件存 Redis List（30min），`?seq=N` 支持断线续传；worker→Redis→api 转发，天然可扩容。

**模板与主题不匹配怎么办**（实测结论，见 04 文档附录 A）：不拦截，靠 system_prompt 里的"输入处理规则"调和——主题 100% 服从用户，文风人格 100% 服从模板。

## 9. 常见问题（速查）

| 现象 | 解法 |
|---|---|
| 生成"准备中"无输出 | ARQ worker 没启动，或 .env 没填 DEEPSEEK_API_KEY |
| `no provider available` | DeepSeek 和 GLM 的 key 都没配 |
| 连不上 MySQL/Redis | `docker compose ps` 看容器；本机 MySQL 走 13306（3306 被原生 MySQL80 占） |
| ARQ 启动报 Redis Timeout | Docker 引擎刚起端口代理未就绪，等几秒重启；2026-10-17 已修 `worker.py` 的 `redis_settings` |
| push 超时 | 开代理；或 `git -c http.proxy= -c https.proxy= push` |
| 想清库重来 | `python -X utf8 -m app.seeds && python -X utf8 -m scripts.import_prompts` |
| 中文乱码 | 命令带 `-X utf8`；PyCharm 运行配置加 `PYTHONUTF8=1` |
| 本机部署其他 Docker 项目 | 互不影响：本项目固定项目名 `myjqr`/专属网络/`myjqr-*` 容器名；只有宿主机端口是全局的，冲突改 `.env` 的 `*_HOST_PORT` |
