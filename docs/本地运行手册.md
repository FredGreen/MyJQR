# MyJQR 本地运行手册（Windows）

> 目标：从零把项目在你这台电脑跑起来，能注册、能选模板、能流式生成一篇文章。
> 当前机器（2026-10-17 迁移，D:\workspace\pyworkspace\MyJQR）已具备：Python 3.14.6 ✅、Node 24 ✅、Git ✅、Docker Desktop ✅ —— MySQL/Redis 用 Docker 起。
> ⚠️ 本机装有原生 MySQL80 服务（占 3306 端口，与本项目无关），所以项目 Docker MySQL 映射到 **13306**，`.env` 已配好。

## 二、环境安装（只缺两样：MySQL + Redis，推荐用 Docker 一次解决）

### 方式 A（推荐）：装 Docker Desktop
1. 下载：https://www.docker.com/products/docker-desktop/ → 安装后重启（需开启 WSL2，安装器会提示）
2. 验证：`docker --version` 有输出、`docker info` 能连上引擎即可
3. 只起数据库两个容器（前后端仍本机跑，改代码即时生效）：
   ```bash
   cd D:\workspace\pyworkspace\MyJQR
   docker compose up -d mysql redis
   ```
   （compose 已把端口映射到本机 127.0.0.1:13306 / 6379；3306 是因为本机原生 MySQL80 占用，改 `.env` 的 `MYSQL_HOST_PORT` 可调）

   **与其他 Docker 项目互不干扰**：本项目 compose 固定项目名 `myjqr`、专属网络 `myjqr-net`、
   容器名 `myjqr-mysql`/`myjqr-redis` 等，卷自动带 `myjqr_` 前缀。本机再部署别的 Docker 项目时，
   各自 `docker compose` 目录下操作即可互不影响；唯宿主机端口是全局资源，冲突时改各自 `.env` 的端口变量。

### 方式 B（不想装 Docker）：原生安装
- MySQL 8：https://dev.mysql.com/downloads/installer/ 装社区版，root 密码设为 `myjqr_root`（或随意，改 .env 对应）
- Redis：Windows 无官方版 → 装 **Memurai**（Redis 兼容，https://www.memurai.com）或 WSL2 里 `apt install redis-server`

## 三、首次初始化（共 6 条命令，顺序执行）

```bash
# ① 配置环境变量（仓库根目录）
cd D:\workspace\pyworkspace\MyJQR
copy .env.example .env
#    本机已生成好 .env（2026-10-17 迁移时）：主机名已默认 localhost、
#    MySQL 端口已按 13306 配好。你只需填 DEEPSEEK_API_KEY（必须）。
#    说明：全量 Docker 部署时无需再改回容器主机名——compose 的
#    environment 会自动把容器内 DSN 覆盖成 mysql:3306 / redis:6379。

# ② 后端依赖（本机已用 .venv 装好；重建时执行）
cd backend
..\.venv\Scripts\pip install -r requirements.txt

# ③ 建表 + 种子数据（15 分类 / 10 内置模板 / 敏感词 / admin 账号）
..\.venv\Scripts\python -X utf8 -m app.seeds

# ④ 导入你的 54 个提示词模板库（xlsx → 数据库）
..\.venv\Scripts\python -X utf8 -m scripts.import_prompts
#    先看看会导入什么（可选）：..\.venv\Scripts\python -X utf8 -m scripts.import_prompts --dry

# ⑤ 启动 API（开发热重载）
..\.venv\Scripts\python -m uvicorn app.main:app --reload --port 9000

# ⑥ 另开一个终端启动 ARQ worker（真正调模型干活的进程）
cd D:\workspace\pyworkspace\MyJQR\backend
..\.venv\Scripts\python -m arq app.tasks.worker.WorkerSettings
```

前端（再开两个终端）：
```bash
cd D:\workspace\pyworkspace\MyJQR\apps\web   && npm run dev    # 用户端 http://localhost:8080
cd D:\workspace\pyworkspace\MyJQR\apps\admin  && npm run dev   # 后台    http://localhost:8081/admin/
```
（两个前端都已把 `/api` 代理到 localhost:9000，无需额外配置）

## 五、常见问题

| 现象 | 原因与解法 |
|---|---|
| `Can't connect to MySQL` | 容器没起：`docker compose ps` 看状态；确认连的是 **13306**（本机 3306 被原生 MySQL80 占用） |
| ARQ worker 连不上 Redis（Timeout connecting to server） | Docker 引擎刚启动时端口代理未就绪，等几秒重启 worker；2026-10-17 已修复 worker 不读 .env REDIS_URL 且连接超时仅 1s 的问题（`app/core/redis.py`） |
| 生成报 `no provider available` 但 .env 明明填了 Key | **worker 是填 Key 之前启动的**——改 .env 后 uvicorn 会自动重载但 worker 不会，去终端② Ctrl+C 重启 worker |
| 生成一直"准备中"没输出 | ARQ worker 没启动（终端⑥），或 `.env` 没填 DEEPSEEK_API_KEY |
| 生成直接报错 `no provider available` | 两个模型 key 都没配 |
| 接口 401 跳回登录 | token 过期（2小时），重新登录即可 |
| 中文乱码 | 命令行加 `-X utf8` 参数（手册命令已带） |
| 3306/6379/9000 端口占用 | MySQL 走 13306 已避开本机 MySQL80；其余端口 `netstat -ano | findstr :6379` 找 PID 处理，或改 `.env` 对应 `*_HOST_PORT` 后 `docker compose up -d` 重建 |
| 想重置全部数据 | `..\.venv\Scripts\python -X utf8 -m app.seeds`（会清库重建）再跑导入脚本 |

## 七、用 PyCharm 启动（推荐日常开发方式）

后端两个进程（API + ARQ worker）都可以在 PyCharm 里一键启动/调试（断点直接打进生成管道）：

### 7.1 工程准备
1. PyCharm → Open → 选 **`MyJQR` 根目录**（不要只开 backend）
2. 右键 `backend` → **Mark Directory as → Sources Root**（让 `import app` 生效）
3. Settings → Project → Python Interpreter → **Add Interpreter → Add Local Interpreter → Select existing**
   选仓库根下的 `.venv`（2026-10-17 迁移时已建好并装完依赖），不用再新建 venv

### 7.2 运行配置（Run → Edit Configurations → ➕ Python）

| 配置名 | Module name（选"Module name"而非 Script） | Parameters | Working directory |
|---|---|---|---|
| **MyJQR API** | `uvicorn` | `app.main:app --reload --port 9000` | `MyJQR/backend` |
| **MyJQR Worker** | `arq` | `app.tasks.worker.WorkerSettings` | `MyJQR/backend` |
| Seeds（初始化用） | `app.seeds` | （空） | `MyJQR/backend` |
| 导入提示词 | `scripts.import_prompts` | `--dry`（正式导入去掉） | `MyJQR/backend` |

> PyCharm **Professional** 也可以直接选 "FastAPI" 类型配置（Application file 选 `app/main.py`），
> 效果一样；Community 版用上表的 Module 方式即可。
> 中文乱码：三个配置的 Environment variables 里加 `PYTHONUTF8=1`。
> `.env` 已固定从 `MyJQR/.env` 读取，Working directory 填错也不影响 Key 加载。

### 7.3 前端
PyCharm 专业版可建 npm 运行配置（package.json → 旁边绿色 ▶）；社区版直接用内置终端：
```bash
cd apps/web  && npm run dev
cd apps/admin && npm run dev
```

### 7.4 调试小技巧
- 想看生成管道内部：在 `app/pipelines/single.py` 打断点 → Worker 配置关掉（Debug 启动 Worker）→ 网页发起生成即可命中断点；
- API 热重载只对 uvicorn 生效，**改了 tasks/ 或 pipelines/ 要重启 Worker**。
